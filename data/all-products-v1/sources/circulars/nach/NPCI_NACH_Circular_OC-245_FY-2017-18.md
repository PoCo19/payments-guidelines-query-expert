Sub:-Deactivationof CPSMS'scheme code in NACHand processing of DBT/non-DBT
transactions
It has been observed that the transactions are still being uploaded in NACH with the
generic code‘CPSMs'despite repeated follow up and engagement with the sponsor banks
on the same.In the month of August 2017, 10.43 Mn transactions have been uploaded in
CPSMS scheme by the sponsor banks making it impossible for NPCI to identify the schemes
and raise claim for incentive and charges as mandated by Department of Expenditure.
The transactions are routed to the sponsor banks in the following ways:
1.PFMS
2.Directlyfromthedepartments
3. Corporates and other entities
As you are aware DBT mission has consolidated all the schemes and issued a consolidated
list of schemes with a unique scheme code for each scheme vide their OM No.D-
11011/02/2016-DBT(Cab)(Pt.)dated December 9,2016for 84 schemes.Currently the
number of DBT schemes have gone up to 354 as on August 25, 2017 (Annexure 1). The
process of marking schemes as DBT is an on-going process and the updated list is available
at www.dbtbharat.gov.in for which the access has been given to Implementing
departments.
the transactions. While many departments have started sending the scheme codes, a few
are still to adopt the codes.
It hasbeendecided to de-activate'CPSMs'code fromNACHmaster witheffectfrom
October 1,2017.The memberbanks should follow theprocess detailed below so that all
the transactions can be put through NACH system so that credits to the end beneficiary is
afforded.
1.If the 5 digit scheme code is provided to the sponsor bank along with the state
details, then bank should approach NPCl for obtaining the relevant user code to be
used for that state. On allotment, bank should start using the relevant code.
2. If the state cannot be identified, then banks should obtain all India user code from
NPCl and process the transactions with the specific scheme code provided in the
input data bythe department.
3. If the scheme and other details are not known then the transactions should be
presented under product code “1o " (ten space). Sponsor banks having such data to
be uploaded should approach NPCl before September 30, 2017 for obtaining the
user code.

4. Existing user codes used for presenting CPsMs transaction will be disabled and

dated February 26,2016 and clarification on June 1,2016,NPCl will continue to raise
claims for charges and incentive to the Ministry of Rural Development for its schemes-
MGNREGA,NSAPandPMAYor toanyother central Ministry if the schemesand the
respective departments on which claims are tobe raised are identifiable.
All other transactions will be treated as normal Non-DBT NACH transactions and will be
charged as per the card rate provided by NPCl.
Please note that NPC will submit the claims to the respective departments and disburse
the amount received purely based on the scheme code used by the sponsor banks. The
responsibility of uploading transactions inappropriate schemecodes lies withthe sponsor
banks. In case any commission/omission detected at a later stage on investigation/audit
findings, the charges/incentives already credited to the sponsor banks/destination banks
would have to be reversed without prior notice. Sponsor banks will be primarily
responsibleforsuchlapse.
