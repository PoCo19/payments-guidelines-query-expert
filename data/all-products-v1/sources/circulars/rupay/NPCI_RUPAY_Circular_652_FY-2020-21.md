Sub: Revision of Incoming file Naming convention for Offline Presentments, to help Issuers clearly 
distinguish, identify and consume for processing 
 
Network Incoming files are generated by the BCS RGCS settlement system and shared with the Issuing members 
after each settlement cycle. RuPay currently generates two incoming files for the Issuing members as detailed 
below, subject to transaction availability.  
1. All Offline Presentments claimed by the Acquiring Members for the cycle. 
2. All other incoming instructions as applicable. 
 
Existing Functionality 
Both incoming files follow the same File Naming convention as detailed in the “RuPay Global Clearing and 
Settlement Technical Message Specification” document as tabulated below.  
Description 
Value 
Interpretation 
File Type 
01 
01 – signifies that this file is a network generated incoming message 
Clearing Cycle 
Number 
1 or 2 
1 – signifies the first clearing cycle 
2 - signifies the Second clearing cycle 
Participant ID of 
Member 
ABCD2110002
This is the participant ID assigned by NPCI to the member. It identifies 
the member who will be receiving this file 
Julian Date 
11213 
Format = YYDDD, i.e. year = 2011 & Julian date = 213 i.e. 1st August 
Sequence Number 
00 or 01 
00 – signifies that this is the first incoming file that has been generated 
for this particular participant for the specified Julian date. 
01 – signifies that this is the second incoming file that has been 
generated for this particular participant for the specified Julian date. 
Sample files names where both offline and normal incoming file is generated in the same settlement cycle. 
1. Incoming file 1: 011ABCD21100021121300 
2. Incoming file 2: 011ABCD21100021121301
