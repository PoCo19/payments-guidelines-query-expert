# Migration and rollback — v0.3

## Completed migration

1. Copied v0.2 code, UI, configuration, tests and guides into `versions/v0.2.0/`.
2. Preserved `data/embeddings.json` (428 original vectors) and its legacy corpus fingerprint.
3. Created `.venv` with Python 3.12.14; installed Chroma 1.5.9 and froze dependencies.
4. Imported legacy vectors into an isolated Chroma collection without re-embedding.
5. Compared JSON cosine search and Chroma with the same query vectors: all 24 top-six ID sequences matched across 12 questions and two retrieval methods.
6. Built 916 new clause-aware vectors and a matching SQLite registry snapshot. Configured the application for clauses-v1 + Chroma + related context.

The old source Markdown/page text was not rewritten. New chunks are derived data. Original PDFs remain in the earlier research pack.

## Reproduce or rebuild

Run from the project root with Ollama running:

```powershell
.\setup.cmd
.\.venv\Scripts\python.exe app.py migrate --config evaluation/migration_config.json
.\run.cmd embed
.\run.cmd validate
```

Migration configuration uses legacy-v1 chunks and Chroma. Its `migration_source_digest` records the embedding model used for the original vectors, verified during this migration. The old JSON cache did not itself record a digest; do not arbitrarily change this value to import vectors generated by an unknown model. Migration rejects a fingerprint, model-name or expected-digest mismatch.

`embed` uses current `config.json` and creates a new complete snapshot. It checks vector count/dimensions/finite values and model digest stability. Failed builds keep the previous active Chroma manifest. Fingerprint changes select a different logical index and require a build. Restart the server after maintenance; an already-running process keeps its loaded snapshot.

## Back up the current version

Stop the app before copying active databases. Back up code/config/docs, `data/` (including Chroma and registry), and the original source pack if preserving PDFs. `.venv` can be recreated from `requirements-lock.txt`; Ollama models must be installed separately. Retained collection snapshots increase disk usage. No automatic snapshot cleanup is provided.

## Inspect the legacy baseline without restoring files

Stop the current app or use another port:

```powershell
.\.venv\Scripts\python.exe app.py serve --config versions/v0.2.0/config.json --port 8766
```

This uses the current v0.3 engine/UI with legacy-v1 chunking and the preserved JSON vector cache. Select **Direct matches only** to avoid the new expansion behavior. This is a diagnostic compatibility mode, not an exact v0.2 UI restoration.

## Full v0.2 rollback

First stop the server, then copy the current code/config/UI somewhere safe. Restore the following from `versions/v0.2.0/` into the project root, overwriting their corresponding current files: `app.py`, `config.json`, `run.cmd`, `run.ps1` and the `web/` directory. Restore old guides/tests/evaluation too if you want a matching historical workspace. Keep `data/embeddings.json` and all source data; no need to delete new Chroma/SQLite data. Launch the restored `run.cmd`.

Do not run the backup's `app.py` directly from inside `versions/v0.2.0`: it expects data relative to its own folder, and this code-only backup does not contain a second source corpus. Full file restoration has not been executed because it would replace the delivered v0.3; baseline compatibility and migration parity have been checked.

## Portability

The tested runtime is Windows/Python 3.12. Update `source_pack` for the PDF directory on another computer. The structured extracted text is local to this project and usable without that PDF folder. Package pins are recorded, but other platforms/Python versions have not been validated.
